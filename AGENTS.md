# Инструкции для работы с Roamly

Эти правила относятся ко всему репозиторию. При изменении инструментов или структуры
обновляйте этот файл и README. Источник актуальных команд и версий — `package.json`
и `package-lock.json`.

## Состояние проекта

Roamly — стартовое клиентское приложение на Vue 3.5, TypeScript 5.8 и Vite 6.
Используются ES modules, Composition API и Vue SFC с `<script setup lang="ts">`.
Сейчас в проекте демонстрационный экран Vite/Vue; предметная логика, маршрутизация,
хранилище состояния, backend и тестовый фреймворк ещё не добавлены.
Не вводите их без необходимости для текущей задачи.

## Структура

- `src/main.ts` — создание приложения, подключение глобальных стилей и монтирование.
- `src/App.vue` — корневой компонент.
- `src/components/` — компоненты Vue; имена файлов в PascalCase.
- `src/style.css` — глобальные стили; локальные стили компонентов помещайте в `<style scoped>`.
- `src/assets/` — ресурсы, обрабатываемые Vite.
- `public/` — статические файлы, доступные от корня сайта, например `/vite.svg`.
- `vite.config.ts` — конфигурация сборщика и алиасов.
- `tsconfig.app.json` — настройки TypeScript для приложения.
- `tsconfig.node.json` — настройки TypeScript для конфигурации Vite.
- `eslint.config.js` — flat config ESLint.
- `.prettierrc.json` и `.prettierignore` — настройки форматирования.
- `.vscode/settings.json` — исправления ESLint при явном сохранении и форматирование
  Prettier в VS Code/Cursor; рекомендованные расширения — в `.vscode/extensions.json`.

## Зависимости и запуск

Используйте npm и сохраняйте `package-lock.json`. Для установки по lock-файлу
выполняйте `npm ci`; при добавлении зависимостей обновляйте оба файла через npm.
Не добавляйте lock-файлы других пакетных менеджеров.

Текущая настройка проверена на Node.js 20.16. Версии `typescript-eslint`
и `@typescript-eslint/parser` закреплены на 8.48.1 для совместимости с этим окружением.
Обновляйте их согласованно и проверяйте требования к Node.js у новых зависимостей.

| Команда                | Назначение                                              |
| ---------------------- | ------------------------------------------------------- |
| `npm run dev`          | Сервер разработки                                       |
| `npm run build`        | Проверка типов и production-сборка в `dist/`            |
| `npm run preview`      | Локальный просмотр предварительно собранного приложения |
| `npm run lint`         | ESLint; предупреждения приводят к ошибке                |
| `npm run lint:fix`     | Исправление поддерживаемых ESLint проблем               |
| `npm run format`       | Форматирование проекта с изменением файлов              |
| `npm run format:check` | Проверка форматирования без изменения файлов            |
| `npm run type:check`   | Проверка типов через `vue-tsc -b`                       |
| `npm run check`        | Последовательный запуск lint, format:check и type:check |

## Правила кода

- Для импортов внутри `src/` используйте алиас `@`, например
  `import HelloWorld from '@/components/HelloWorld.vue'`.
  Алиас должен оставаться согласованным в `vite.config.ts` и `tsconfig.app.json`.
- Пишите компоненты с `<script setup lang="ts">`, типизируйте props и события.
- Сохраняйте строгие настройки TypeScript. Используйте `import type` для импорта типов.
  Не отключайте проверки и правила ESLint ради обхода ошибки; исправляйте её причину.
- ESLint проверяет код по рекомендуемым правилам JavaScript, TypeScript и Vue.
  В `src/` запрещён `console.log` правилом `no-restricted-properties` (ошибка).
  Плагин `eslint-plugin-unused-imports` удаляет неиспользуемые импорты при
  `lint:fix` и явном сохранении в VS Code/Cursor с расширением ESLint.
  Его правило `unused-imports/no-unused-vars` сохраняет проверку неиспользуемых
  переменных вместо базовых правил, чтобы не дублировать ошибки импортов.
  Проверку типов выполняет отдельная команда `type:check`.
  Правило `@typescript-eslint/consistent-type-imports` автоматически приводит
  импорты типов к отдельным `import type` при исправлениях ESLint.
- Форматирование поручайте Prettier: два пробела, одинарные кавычки в JS/TS,
  без точек с запятой, завершающие запятые, ширина строки 100 символов.
  Сохраняйте `eslint-config-prettier` последним в конфигурации ESLint,
  чтобы отключать конфликтующие правила оформления.
- Следуйте существующему стилю обычного CSS; новые библиотеки добавляйте
  только при необходимости для задачи.

## Проверка изменений

После изменения кода или конфигурации выполняйте `npm run check` и `npm run build`.
Для изменений только документации достаточно проверки форматирования изменённых файлов.
После изменения интерфейса по возможности проверьте соответствующий экран в браузере.
Сообщайте, какие проверки выполнены, и явно указывайте непроверенные части.

Команды `test` пока нет. Не описывайте проверку типов или сборку как запуск тестов.
При необходимости тестирования новой логики выбирайте инструменты соразмерно задаче.

## Работа с файлами

Сохраняйте существующие пользовательские изменения и ограничивайте правки текущей задачей.
Не редактируйте вручную и не коммитьте `node_modules/`, `dist/`, `dist-ssr/`
и временные результаты инструментов. Перед коммитом просматривайте diff;
избегайте форматирования посторонних файлов.
